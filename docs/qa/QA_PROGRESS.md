# QA progress log

This log tracks Phase 3 (remediation) of [QA_PLAN.md](QA_PLAN.md). The plan's 7 columns stay unchanged; status and evidence for each task live here.

**Statuses:**

- `DONE`: fixed, with passing automated tests as evidence.
- `PARTIAL`: the repository side is fixed, but part of the task needs a human.
- `BLOCKED: <reason>`
- `NEEDS HUMAN`: nothing can be done in the repo until a person decides or acts.

**Branching:** the QA branches are stacked on `stage`. Each `qa/<task-id>-<short-name>` branch starts from the previous one, so the newest branch holds every fix. Per the owner's instruction, the owner merges it to `dev` when QA is finished.

**Gate run for every task:** the task's own new tests, then:

- `bun run format:check`
- `turbo check-types` and `lint` (mobile excluded, as in CI)
- `turbo test` (unit)
- the full DB-backed API suite (`apps/api: bun test`)
- `bun run test:security`
- task-specific suites and scans, where relevant

Everything runs locally, against disposable Postgres and Redis containers only.
