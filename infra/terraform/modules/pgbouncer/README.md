# `pgbouncer`

A single EC2 instance running PgBouncer in transaction-pooling mode in front of
`module.postgres`, with one pool per service, TLS on the client-facing listener, and
pool-saturation metrics pushed to CloudWatch. Pooling-mode rationale (why transaction mode, and
what it means for `SET` vs. `SET LOCAL`) and the auth/TLS design:
[`docs/runbooks/pgbouncer-conventions.md`](../../../../docs/runbooks/pgbouncer-conventions.md).

## What this module does not do

- **It does not create a network or security group.** Pass `subnet_id` and `security_group_ids`
  from `module.network` (`private_app_subnet_ids[0]`, `pgbouncer_security_group_id`) — same
  division of responsibility as every other module here.
- **It does not provide high availability.** One instance, not an Auto Scaling Group behind a
  load balancer. `modules/postgres` and `modules/redis` are fixed HA pairs because their tickets
  asked for HA; this ticket didn't, and a second instance needs a load balancer (or a stable
  private DNS name) this repo has no precedent for yet. A single instance is a real single point
  of failure between the app tier and the database — acceptable for this ticket's scope, not a
  hidden gap.
- **It does not create a per-service Postgres role.** Only the master credential exists
  (`docs/runbooks/postgres-conventions.md`'s "Known gaps"). Every `service_pools` entry
  authenticates to Postgres as that same master user; "per-service pools" here means per-service
  **connection budgets** (`pool_size`), not per-service database privileges. Least-privilege
  per-service roles are a follow-up scoped to whichever ticket adds the first schema/migration.
- **It does not run a Prometheus exporter.** No Prometheus/Grafana stack exists in this repo —
  every other module's observability is CloudWatch-native (VPC flow logs, the bastion's shipped
  SSH log). `SHOW POOLS`'s columns are parsed directly by a small script and pushed to CloudWatch
  as custom metrics instead of introducing a second metrics system for one module.
- **It does not verify `dnf install pgbouncer` against a real Amazon Linux 2023 apply.** This was
  written without an AWS account to test against; if PgBouncer isn't in AL2023's default repos by
  the time this is applied, `user_data` fails at boot and the instance never becomes reachable.
  Check `aws ssm start-session` / the instance's console output first if the acceptance criteria
  don't pass on first apply — see "Troubleshooting" below.

## Topology

```
module.network's app SG ──► pgbouncer SG:6432 ──► db SG:5432 (module.postgres)
module.network's bastion SG ──► pgbouncer SG:6432 (admin console / SHOW POOLS)
```

One `aws_instance` in a private-app subnet (needs outbound NAT for package installs and the
Secrets Manager/CloudWatch API calls in `user_data` — same tier the bastion's EIP-free traffic
would eventually share with real app compute). `pool_mode = transaction`, globally: every pool
this module configures hands a server connection back the moment a transaction commits, not when
the client disconnects.

## TLS

A self-signed CA (`tls_self_signed_cert`, `is_ca_certificate = true`) signs a leaf certificate for
the instance; PgBouncer's `client_tls_*` settings require TLS on every incoming connection. Not
ACM: ACM certificates' private keys aren't exportable for a listener ACM itself doesn't terminate,
and ACM Private CA is unjustified cost/complexity for one instance. Clients should use
`sslmode=verify-ca` with the `ca_cert_pem` from `connection_secret_arn` — not `verify-full`,
because this instance has no stable DNS name (no Route 53 private zone exists) for a certificate
SAN to match against.

The connection to Postgres itself (`server_tls_sslmode = require`) rides on top of RDS's own
`rds.force_ssl = 1` (`modules/postgres`) — belt-and-suspenders, not the only enforcement.

## Auth

`userlist.txt` holds two entries, both written as plaintext (not MD5/SCRAM hashes — PgBouncer only
ever has the plaintext to work with, since no per-service Postgres role/hash exists to pull from):

| User                     | Purpose                                                      | Source                                             |
| ------------------------ | ------------------------------------------------------------ | -------------------------------------------------- |
| Postgres master username | Every `service_pools` database entry's auth                  | `postgres_connection_secret_arn`, fetched at boot  |
| `pgbouncer_stats`        | Admin-console `SHOW POOLS`/`SHOW STATS` only, not full admin | Generated by this module (`random_password.stats`) |

`admin_users` is the master user (full `RELOAD`/`PAUSE`/`KILL`); `stats_users` is the dedicated
stats user the metrics script actually runs as, so a compromised metrics script can't pause or
kill pools.

## Metrics

A systemd timer runs `pgbouncer-metrics.sh` every `metrics_interval_seconds` (default 60s): it
runs `SHOW POOLS` against the local admin console and pushes six data points per pool to
CloudWatch under `cloudwatch_metrics_namespace`:

| Metric           | `SHOW POOLS` column | What it means                                                                                                       |
| ---------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `ClientsWaiting` | `cl_waiting`        | **The saturation signal.** Sustained > 0 means every server connection in the pool is busy and clients are queuing. |
| `ClientsActive`  | `cl_active`         | Clients currently assigned a server connection.                                                                     |
| `ServersActive`  | `sv_active`         | Server connections currently in a transaction.                                                                      |
| `ServersIdle`    | `sv_idle`           | Server connections idle, available for the next transaction.                                                        |
| `ServersUsed`    | `sv_used`           | Server connections idle but not yet returned to the free list.                                                      |
| `MaxWaitSeconds` | `maxwait`           | Longest a currently-waiting client has been queued.                                                                 |

Each is dimensioned by `Pool` (the `service_pools` key). A CloudWatch alarm on `ClientsWaiting > 0`
for a sustained period, per pool, is the natural next step — not created by this module, since no
alerting destination (PagerDuty/Slack/SNS topic) exists yet in this repo to alarm into.

## Troubleshooting

SSH in via the bastion (requires `key_name` to be set):

```bash
ssh -J ec2-user@<bastion_public_ip> ec2-user@<pgbouncer private_ip>
sudo journalctl -u pgbouncer -u pgbouncer-metrics --since "10 min ago"
```

Or read the shipped log without SSH access at all:

```bash
aws logs tail "$(terraform output -raw pgbouncer_log_group_name)" --follow
```

## Usage

```hcl
module "pgbouncer" {
  source = "./modules/pgbouncer"

  name_prefix                    = module.naming.name_prefix
  subnet_id                      = module.network.private_app_subnet_ids[0]
  security_group_ids             = [module.network.pgbouncer_security_group_id]
  postgres_connection_secret_arn = module.postgres.connection_secret_arn
  listen_port                    = var.pgbouncer_port
}
```

## Inputs

| Name                             | Type                                            | Default                                           | Description                                                                        |
| -------------------------------- | ----------------------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `name_prefix`                    | `string`                                        | —                                                 | Resource name prefix, from `module.naming.name_prefix`.                            |
| `subnet_id`                      | `string`                                        | —                                                 | `module.network.private_app_subnet_ids[0]`.                                        |
| `security_group_ids`             | `list(string)`                                  | —                                                 | `[module.network.pgbouncer_security_group_id]`.                                    |
| `postgres_connection_secret_arn` | `string`                                        | —                                                 | `module.postgres.connection_secret_arn`.                                           |
| `listen_port`                    | `number`                                        | `6432`                                            | Must match the network module's `pgbouncer_port`.                                  |
| `instance_type`                  | `string`                                        | `t3.micro`                                        | Dev-appropriate default only — no researched staging/prod sizing yet.              |
| `key_name`                       | `string`                                        | `null`                                            | Existing EC2 key pair for SSH via the bastion. `null` disables SSH.                |
| `service_pools`                  | `map(object({ pool_size, reserve_pool_size }))` | `{ api = 20/5, realtime = 10/0, workers = 10/5 }` | One `[databases]` entry per key; keeps `modules/registry`'s default service names. |
| `max_client_conn`                | `number`                                        | `200`                                             | Hard ceiling on total client connections across every pool.                        |
| `default_pool_size`              | `number`                                        | `20`                                              | Fallback for a database not in `service_pools`; not actively used.                 |
| `cloudwatch_metrics_namespace`   | `string`                                        | `Studafy/PgBouncer`                               | Namespace the metrics script publishes to.                                         |
| `metrics_interval_seconds`       | `number`                                        | `60`                                              | How often the systemd timer runs the metrics script.                               |
| `log_retention_days`             | `number`                                        | `90`                                              | CloudWatch Logs retention for the shipped `pgbouncer.log`.                         |
| `root_volume_size_gb`            | `number`                                        | `8`                                               | Root EBS volume size.                                                              |

## Outputs

| Name                           | Description                                                                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `instance_id`                  | EC2 instance ID.                                                                                                                                                |
| `private_ip`                   | Not sensitive on its own — combine with the credential in `connection_secret_arn`.                                                                              |
| `port`                         | Echoes `var.listen_port`.                                                                                                                                       |
| `connection_secret_arn`        | Secrets Manager ARN holding port, sslmode, the CA cert, and the stats-user credential (no host — see `private_ip`). The Postgres master password is never here. |
| `log_group_name`               | Where the shipped `pgbouncer.log` lands.                                                                                                                        |
| `cloudwatch_metrics_namespace` | Echoes `var.cloudwatch_metrics_namespace`.                                                                                                                      |
